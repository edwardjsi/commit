#Day 43 – Configuration Management with Ansible (Puppet vs Ansible)

## Goal

Understand why Configuration Management is needed and why Ansible is preferred over agent-based tools like Puppet for modern infrastructure.

## What I did

* Studied the need for Configuration Management to replace inconsistent shell and PowerShell scripts across servers.
* Compared Ansible and Puppet across core dimensions: agent model, execution model, language, and protocol.
* Documented why Ansible’s agentless, push-based approach is better suited for scalable and simpler operations.

## What this proves

* I understand the real operational problems Configuration Management solves.
* I can clearly explain the architectural differences between Ansible and Puppet.
* I choose tools based on design trade-offs, not popularity.

## How this helps a client/employer

* I can standardize configuration across environments reliably.
* I can reduce maintenance overhead by avoiding agent management.
* I can select the right CM tool aligned with security, simplicity, and scalability.
